# Resident appointment and follow-up reminders

Run `php follow-up-reminder-job.php` every 15 minutes on the machine hosting the database. This CLI job runs independently of website traffic, creates portal notifications, and sends resident email and subscribed browser push reminders for appointments and follow-ups due today or tomorrow in Asia/Manila. Completed consultations can still have a future follow-up; cancelled or rescheduled reminders are rechecked before sending. Successful deliveries are remembered per reminder and channel; failed emails retry on the next run without repeating successful pushes.

`php follow-up-reminder-job.php --check` checks the database connection and whether an SMTP password is configured without sending. It does not authenticate with SMTP or verify inbox delivery. `php check-reminder-smtp.php` checks TLS and SMTP authentication without sending email. The latest run summary is in `scratch/reminder-job-status.json`; SMTP delivery results are logged in `scratch/mail-delivery.log`. No email content is stored in these logs. A successful SMTP result means the receiving server accepted the message, not that the resident opened it or that it avoided their spam folder.

On Windows, run `./install-follow-up-reminders.ps1` to register the **ResiHUnity Follow-up Reminders** task for the signed-in user. It starts after one minute and repeats every 15 minutes. The browser may be closed, but Windows must remain signed in, the machine must be awake, MySQL must be running, and internet access must be available. To run when all users are signed out, an administrator can install the task with `-RunAsSystem` instead. The installer refuses to overwrite an existing task; inspect/remove the existing task before changing the principal.

On a hosted deployment, configure its scheduler/cron with the absolute path to PHP and `follow-up-reminder-job.php`. The job is CLI-only; do not expose an unauthenticated HTTP trigger. A local Windows task does not deploy itself to a remote hosting provider.

InfinityFree free hosting does not support scheduled jobs or external cron requests. Browser-independent reminders cannot run there. Move the application and database to a host that supports PHP CLI cron, or run them on a server you control that stays on. After migration, schedule the job every 15 minutes, run `php follow-up-reminder-job.php --check`, check SMTP authentication, and inspect `scratch/reminder-job-status.json` after the first scheduled run. Do not point an external cron service at a public trigger on the free host.

Browser notifications require a resident to have enabled notification permission and registered the device in the portal at least once. Email does not require the portal to be open when the scheduled job is running. Resident reminder emails require configured SMTP; missing email addresses and unsubscribed devices are counted in the job summary. Failed configured SMTP delivery stays failed for retry instead of being treated as delivered by an unrelated fallback relay.

Regression checks: `php tests/resident-reminders-test.php`. The tests use an isolated database and fake delivery functions; they send no real messages.
