# Inventory ownership and stock history

Open **Inventory** from a staff/admin header. InventoryManagement.php shows current medicines, laboratory kits, supplies and equipment. All authenticated staff can record usage. Only a System Administrator (rhu_admin_authenticated or RHU_ADMIN/SUPER_ADMIN staff account) can create items/batches or receive stock. Secretary, physician, nurse, midwife, dentist, medtech and sanitary staff do not gain stock-add permission through access to the admin dashboard.

Staff supply creation, restock and count-reset controls have been removed. Forged staff additions are rejected server-side. Old medicine addition/adjustment paths direct users to the audited Inventory workflow; they no longer write directly to inventory. Inventory mutation SQL is centralized in inventory-control.php. Staff usage requires a positive whole quantity, service/location and purpose; stock cannot become negative. Medicine expiry checks are retained for received stock. Existing item names are not aggregated for writes: the exact item/batch is selected.

Each new change writes an inventory_movements row containing item name/type/unit snapshots, signed quantity, before/after balances, staff ID/name, service, location, purpose, actual use time, and recording time. Stock receipt uses server recording time. Quantity changes and history share the same InnoDB transaction: a history failure rolls back stock. Item creation is admin-only and includes its opening stock receipt. There is no application route to edit or delete movement history.

Laboratory tests feed material deductions into this ledger with the entered usage location/time. Dental prescriptions that dispense inventory also feed the ledger, with dispensing location/time and patient ID. Staff can use the shared page for other consumable usage. Record a movement only once; the application cannot infer unreported consumption or distinguish an incorrectly repeated manual submission.

Admins can filter the history by dates, movement and text (item, staff, service, location or purpose), print the report, or download all matching detailed rows as CSV. The screen limits detailed history to 200 entries; exports are not capped. Older stock_transactions records are shown separately (up to 100 for the date range) and have a separate uncapped CSV export. Missing historical staff/location/service information is not invented. Records of older usage that were never logged cannot be reconstructed from inventory balances.

The stock-history schema is initialized automatically before stock transactions; schema DDL is never issued inside a stock transaction. Existing stock balances are not changed during initialization. Database backups should include inventory_movements along with medicine_inventory. The staff inactivity/PIN lock covers the new page. Forms use existing portal CSRF verification; history and history exports are admin-only. CSV text is escaped against spreadsheet formula execution.

Verification: php tests/inventory-control-test.php checks admin-only additions, staff usage, staff attribution, required location, insufficient stock and rollback on history failure. Local database checks rendered admin and staff views and validated detailed/legacy CSV exports. An isolated inventory item and history movement were created inside a database transaction for SQL verification and then rolled back; no existing stock or patient records were changed. PHP syntax checks, patient-ID checks and lock policy checks passed.
